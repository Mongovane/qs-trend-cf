# 实盘 / 模拟盘接入

## 职责划分

```
历史回测   →  npm run bt              （TypeScript，与看板共用分析引擎）
信号产出   →  Cloudflare /api/*       （唯一信号源）
模拟盘执行 →  QMT 或 PTrade 脚本      （只执行，不重算信号）
```

**为什么执行脚本不重新实现评分逻辑**：同一策略维护两份实现，一定会分叉。
届时看板说买、实盘说卖，你无法判断哪个对。所以执行端一律从接口取信号。

代价是执行端依赖网络。QMT 脚本跑在你自己机器上没问题；PTrade 的**回测环境
无外网**，因此 PTrade 策略在回测模式下会主动拒绝运行并提示改用 `npm run bt`。

---

## 一、迅投 QMT

### 环境

- Windows + QMT 客户端（券商提供，需申请 miniQMT 权限）
- QMT → 设置 → 模型交易 → Python，确认 xtquant 可用
- 客户端**保持登录**，脚本通过本地 miniQMT 通道下单

### 导出历史数据用于回测

```bash
python integrations/qmt/export_history.py --start 20200101 --top 300
```

用 QMT 数据而非免费网络接口的三个理由：
1. 前复权口径统一，且带停牌标记，回测才有意义
2. 免费接口的历史数据常缺除权处理，会凭空造出跳空
3. 与你未来实盘的数据源一致，避免「回测一套、实盘一套」

### 模拟账号执行

```bash
# 先空跑，看它想干什么
python integrations/qmt/qmt_paper_trade.py \
    --account 你的模拟账号 --api https://你的域名.pages.dev

# 确认无误后真实报单（仍是模拟账号）
python integrations/qmt/qmt_paper_trade.py \
    --account 你的模拟账号 --api https://你的域名.pages.dev --live
```

内置护栏（代码级硬上限，无命令行覆盖）：

| 护栏 | 值 |
|---|---|
| 单日最大下单笔数 | 50 |
| 单笔最大金额 | 20 万 |
| 最低现金保留 | 5% |
| 非模拟账号 | 拒绝启动，除非显式 `--allow-real` |
| 非交易时段 | 拒绝 `--live` |
| 涨停 / 停牌 | 自动跳过 |

代码格式注意：**QMT 用 `.SH`/`.SZ`/`.BJ`，PTrade 用 `.SS`/`.SZ`**，别混。

## 二、PTrade

### 部署

1. PTrade → 交易 → 新建策略，粘贴 `integrations/ptrade/strategy.py`
2. 改 `CONFIG['API_BASE']` 为你的 Pages 域名
3. `CONFIG['DRY_RUN']` 保持 `True`，先只看日志
4. 用**模拟账号**跑至少一个月，再考虑改 `DRY_RUN=False`

### 执行时点

- `09:35` 调仓（先风控离场，再建仓）
- `14:50` 只做风控离场，不新建仓——避免尾盘冲高接盘

### 与回测口径对齐

策略里的费用设置刻意与 `backtest/src/market.ts` 一致：

```python
set_commission(commission_ratio=0.00025, min_commission=5.0, type='STOCK')
set_slippage(slippage=0.002)
```

两边不一致的话，回测和模拟盘的差异你会归因错。

## 三、上线前的检查清单

- [ ] 用自己的 QMT 数据跑 `npm run bt:wf`，确认**样本外**衰减 < 50%
- [ ] 确认样本外 Sharpe 超过报表给出的噪声上界
- [ ] 确认交易笔数 ≥ 30，否则统计量无意义
- [ ] 检查「开盘涨停买不到」的数量——越大说明收益越依赖拿不到的机会
- [ ] 检查按 `entryScore` 分档后收益是否单调——不单调说明评分无区分度
- [ ] 模拟盘 `DRY_RUN` 观察 ≥ 2 周，核对它的下单计划是否符合预期
- [ ] 模拟盘实际成交 ≥ 1 个月，且**包含一次明显下跌**
- [ ] 对比模拟盘实际成交价与回测假设的滑点差距

## 四、必须说清楚的几件事

**接口稳定性**：本目录的脚本按 2024 年的 xtquant / PTrade 接口编写，
两家都会调整 API 与常量名。首次使用务必 dry-run 并对照你本地版本的文档。
我无法在此环境验证这些接口。

**回测与实盘的差距**来自这些地方，且通常都比预期大：
滑点、成交量约束（回测假设你的单子不影响价格）、涨停买不到、
数据修正（历史数据事后被调整过）、以及最重要的——**你的执行纪律**。

**回测通过不等于策略有效**。它只排除了「明显无效」，样本外检验通过也只是
没被否证。参数是在有限历史上选的，市场结构会变。

**这套评分体系本身未经证明**。所有阈值都是经验值；CANSLIM 的 C/A/I 三维
实际用价格动量替代了财务数据（见 `docs/ANALYSIS.md` 局限性）。
回测框架的价值在于**让你自己判断它值不值得用**，而不是证明它好。

投入真钱的决定和后果都是你自己的。这个仓库只提供工具。
