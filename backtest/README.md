# 回测框架

与线上看板**共用同一份分析引擎**（`src/analysis/`）。这不是为了省事，
而是因为策略维护两份实现必然分叉，最后你无法判断该信哪一个。

---

## 快速开始

```bash
# 1. 引擎自检（合成数据，不需要行情源）
npm run bt:selftest

# 2. 从 QMT 导出真实数据
python integrations/qmt/export_history.py --start 20200101 --top 300

# 3. 单次回测
npm run bt -- run --data backtest/data --benchmark backtest/benchmark.csv

# 4. 滚动窗口优化（这才是有意义的那一步）
npm run bt:wf -- --data backtest/data --benchmark backtest/benchmark.csv
```

## 防未来函数的三条结构性约束

回测最容易出错也最难自查的就是未来函数。本引擎不靠「小心一点」，
而是让它在结构上不可能发生：

**1. 切片隔离** —— 第 t 个交易日调用分析引擎时，只传入 `klines.slice(0, t+1)`。
引擎内部所有 `[-1]` 都指向第 t 天，物理上拿不到后面的数据。

**2. 次日开盘成交** —— 第 t 日收盘后产生的信号，在第 t+1 日**开盘价**成交。
绝不用第 t 日收盘价成交 —— 那等于假设你在收盘前就知道了收盘价。
盘中风控（止损/止盈）也只**登记**卖出意图，同样次日开盘执行。

**3. 基准与资金流同步切片** —— 指数 K 线、资金流一并按日期截断，
否则 CANSLIM 的 M 维度会偷看未来的大盘走势。

## 已建模的 A股约束

| 约束 | 说明 |
|---|---|
| T+1 | 当日买入不可卖出 |
| 一字涨停 | 开盘即涨停无法买入，计入 `rejected.limitUp` |
| 一字跌停 | 开盘即跌停无法卖出，计入 `rejected.limitDown` |
| 停牌 | 成交量为 0 视为停牌，跳过 |
| 涨跌幅限制 | 主板 10% / 双创 20% / ST 5% / 北交所 30% |
| 整手 | 买入按 100 股向下取整 |
| 佣金 | 双边万 2.5，单笔最低 5 元 |
| 印花税 | 卖出 0.05% |
| 过户费 | 双边 0.001% |
| 滑点 | 默认单边 10bp，买入上滑卖出下滑 |

**未成交统计务必看**。如果 `开盘涨停买不到` 很大，说明策略的收益严重依赖
一字板上的成交 —— 那些收益在实盘里拿不到。

## 为什么必须做滚动优化

在同一段历史上试 200 组参数然后挑最好的，几乎必然过拟合。即使策略毫无
预测能力，200 次试验里也总有几组「看起来很棒」——那不是策略好，是你挑出了噪声。

`npm run bt:wf` 的做法：

```
历史切 5 段
  段1+2 优化 → 段3 检验
  段2+3 优化 → 段4 检验
  段3+4 优化 → 段5 检验
只报告样本外拼接净值
```

输出里有三个数字决定结论可信度：

| 输出 | 怎么读 |
|---|---|
| **衰减幅度** | 样本外相对样本内的下降。>50% 基本可判定参数是拟合噪声 |
| **显著性** | 按试验次数计算噪声上界。样本外 Sharpe 低于上界 = 无法与随机区分 |
| **交易笔数** | <30 笔时所有统计量都不可信，报表会打 ⚠ |

## 首次回测就暴露的问题：换手率

用默认参数在合成数据上自检时，引擎立刻暴露出一个**策略层面的结构缺陷**：

```
交易笔数    929        平均持仓  2.5 日
年换手率    30 倍      期望/笔   -0.06%
离场原因    90% 是「信号退化(观望)」
```

原因：信号引擎的 `action` 是**时点建议**，不是持仓状态。评分在 60 分线附近
自然抖动，用同一个门槛做进出就会「今天买、明天卖」，双边费用约 0.24%
（佣金+印花税+滑点）直接吃光收益。

修复方式是标准的**滞后带**（hysteresis）：

```
minScore  = 62   进场线
exitScore = 45   离场线      ← 两者之间是持有区
minHoldDays = 5  最短持仓
```

同一份数据、同一套信号，仅加滞后带后：

| 指标 | 无滞后带 | 有滞后带 |
|---|---|---|
| 交易笔数 | 929 | 180 |
| 平均持仓 | 2.5 日 | 15.7 日 |
| 年换手率 | 30.2 倍 | 6.8 倍 |
| 期望收益/笔 | −0.06% | +0.51% |
| Sharpe | −0.46 | 0.45 |

> ⚠ 上述数字来自**合成数据**，只能证明「换手率问题真实存在且滞后带能解决它」，
> **不能**用来说明策略赚钱。合成序列没有真实市场的截面结构。
> 你必须用自己的 QMT 数据重跑一遍。

顺带说一句：即使加了滞后带，合成数据上的策略仍然**跑输等权基准**
（11.3% vs 37.4%，alpha 为负）。这是个值得警惕的信号。

## 参数

```
--data <dir>          数据目录
--benchmark <file>    基准 CSV
--capital <n>         初始资金
--from / --to         区间
--min-score <n>       进场分数线
--exit-score <n>      离场分数线（滞后带下沿）
--min-hold <n>        最短持仓交易日
--max-hold <n>        最长持仓交易日
--max-positions <n>   最大持仓数
--trailing <0.08>     移动止盈
--stop-mode plan|atr|fixed
--profile enhanced|legacy
--strict              排除「谨慎买入」
--no-compound         按期初资金定仓
```

`--profile legacy` 可以回测原 v4.0 的五模块权重，与 `enhanced` 做 A/B 对比。

---

## 输出

```
backtest/out/equity.json      每日净值
backtest/out/trades.json      逐笔交易明细
backtest/out/metrics.json     绩效指标
backtest/out/walkforward.json 滚动优化结果
```

`trades.json` 建议重点看：按 `exitReason` 分组，看是止损多还是止盈多；
按 `entryScore` 分档，看高分信号是否真的表现更好——如果没有单调关系，
说明评分本身没有区分度。
