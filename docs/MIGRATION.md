# 迁移决策记录

记录本次重构中每个非显而易见的取舍，便于后续维护者理解"为什么这么做"。

---

## D1 · 为什么用 TypeScript 重写而不是跑 Python

**背景**：Cloudflare 有 Python Workers（beta），理论上可以直接跑原代码。

**决策**：全量重写为 TypeScript。

**理由**：
- Pages Functions **不支持** Python，只有 Workers 支持，而 Pages 是需求指定的目标
- Python Workers 目前不支持 `requests`（需 `urllib3` 的 socket 层），而数据层重度依赖它
- Pyodide 冷启动数百毫秒，对秒级刷新的行情看板不可接受
- 分析层是纯标准库实现，移植成本可控（实测约 2600 行 TS）

**代价**：需要一套一致性回归测试来保证移植正确，见 `tests/parity.test.mjs`。

## D2 · 为什么保留 `legacy` 档位

**决策**：即便修复了三个缺陷，仍保留一个逐字段复刻原版的档位。

**理由**：
- 修复 P1 后形态分实测从 49 变到 37，**买卖建议会跟着变**。用户需要能比对
- 没有 `legacy` 就无法写出有意义的回归测试——"和原版一致"必须是可验证的断言
- 历史信号复现需要原始算法

**代价**：`analyzePatterns` / `analyzeTrend` 多一个 `legacy` 参数，略增复杂度。

## D3 · 为什么 `pyRound` 不用乘法实现

**背景**：最直觉的写法是 `Math.round(x * 10**d) / 10**d`。

**决策**：改用「精确十进制展开 + toFixed」实现。

**理由**：乘法会引入 Python 端不存在的浮点误差。实测：

| 表达式 | Python | 乘法实现 | 正确实现 |
|---|---|---|---|
| `round(2.675, 2)` | 2.67 | 2.68 ❌ | 2.67 ✅ |
| 海龟 N 值 | 1.4771 | 1.4772 ❌ | 1.4771 ✅ |

N 值偏差 0.0001 会传导到止损价 → 盈亏比 → 最终买卖建议。
这类问题**肉眼无法发现**，是移植中最危险的坑。

**验证**：`tests/parity.test.mjs` 中有 24 组 round 用例与真实 Python 输出比对。

## D4 · 扫描为什么改成"轮询驱动的状态机"

**背景**：原版 20 线程一次扫完；Workers 没有后台线程，且有子请求上限。

**候选方案**：

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| Cron Worker + Queues | 后台执行，用户无感 | 需第二个部署单元；Queues 是付费功能 | 否决 |
| Durable Objects 编排 | 状态一致性好 | DO 是付费功能 | 否决 |
| **KV 增量状态机** | 纯免费版可用；**前端零改动** | 需保持页面打开 | ✅ 采用 |

**关键巧思**：前端原本就每 2 秒轮询 `/api/scan` 拿进度。把「推进一批」
挂在这个轮询上，前端一行代码都不用改，轮询本身就成了执行引擎。

**代价**：关闭页面会暂停扫描（状态保留在 KV，重开继续）。

## D5 · 缓存为什么用 Cache API 而非 KV

**决策**：行情缓存走 `caches.default`，只有扫描状态用 KV。

**理由**：KV 免费版每天只有 **1000 次写入**。若把行情也写进 KV，
几十次分析就把配额耗尽了。Cache API 无写入配额限制。

**代价**：Cache API 是**按数据中心**隔离的，不同边缘节点各自缓存，
命中率低于 KV。对行情这种高频只读数据可以接受。

## D6 · 为什么移除授权而不是移植

**决策**：整体移除 secp256k1 + 硬件指纹授权。

**理由**：
- 硬件指纹在浏览器里不存在等价物
- 任何跑在客户端的授权校验都能被绕过；跑在服务端则需要用户体系和后端存储
- Cloudflare Access 免费版含 50 席位，在**网络层**拦截，比应用层授权更强

**注意**：如果原作者的商业模式依赖这套授权，公开部署本项目可能有版权问题。
`README.md` 已加提示。

## D7 · 技术指标层的权重怎么定的

**决策**：`enhanced` 档位给技术指标 20% 权重，与趋势模块并列最高。

**理由**：
- 原版五模块中，「趋势」实际只用了 MA20/MA60，「量价」只用了 OBV，
  覆盖面偏窄。补一层多指标共振能显著降低单一指标失效的风险
- 20% 足以影响档位切换（60/75 分线），但不至于喧宾夺主

**归一化设计**：每项指标贡献 ±12，按**实际参与数量**归一到 ±40。
这样上市不足 60 日、DMI/ADX 算不出来的新股不会被系统性压低——
这是一个容易被忽略的细节，若直接除以固定的 12 项，短历史股票会平白少掉 30 多分。

**声明**：这组权重同样**未经回测验证**，是基于常见实践的经验配置。
使用前请自行验证。

## D8 · UI 重做（v5.1）的设计决策

**决策**：整体替换 `<style>` 块，类名 100% 沿用，JS 只做 4 处外科手术式补丁。

**理由**：`index.html` 3400+ 行，JS 与 class 名深度耦合。重写 DOM 结构的收益
远小于风险；而视觉观感几乎全部由 CSS 承担。这条路径用 600 行 CSS 换到了
完整改观，且回归面积可控。

### 三个实质性的设计改动

**1. 交互色与市场方向色分离**

原版把 `#ff9800` 橙色同时用于四种含义：可点击控件、警告状态、MA60 均线、
杯柄买点。结果是「橙色」不携带任何信息——用户无法从颜色判断某个元素是
能点的、是危险的、还是只是条均线。

新方案：
- 蓝 `#5b7cfa` = 可交互（按钮、激活态、链接）
- 红 `#f6465d` / 绿 `#0ecb81` = 且仅= 市场方向
- 黄 `#f0b90b` = 且仅= 警告
- 青 `#2dd4bf` = 数据/关键价位

**2. 全站 `tabular-nums` + 等宽数字**

价格从 1487.320 跳到 1489.005 时，比例字体下字宽会变，整行左右抖动。
交易界面里这个抖动非常烦人。所有数字类元素统一用 `font-variant-numeric:
tabular-nums` + 等宽字体族。原版用的 `'Courier New'` 换成
`ui-monospace / SF Mono / JetBrains Mono` 系统栈。

**3. 分层表面代替纯黑 + 描边**

原版靠 `#000` 底 + `#222`/`#333` 描边划分区块，密集数据下边框噪声很重。
新方案改为三级明度表面（`#0a0c0f` → `#12161b` → `#1a1f26`），
边框统一降到 `rgba(255,255,255,0.07)`，靠明度而非线条区分层次。

### signature：决策环

`.sum-score-big` 从一个 48px 数字改成 `conic-gradient` 径向仪表盘，
由 CSS 自定义属性 `--score` 驱动（JS 只需 `--score:${score}`）。
选它作为唯一的「大胆之处」，因为综合评分是整个产品的核心输出，
值得一个能被记住的形状；其余部分保持克制。

### 微交互

| 效果 | 说明 |
|---|---|
| 价格闪烁 | 同一标的价格变动时红/绿背景闪一下；切换标的时不闪 |
| 深度条 | 模块评分改成订单簿深度条语言，填充 + 右端 2px 亮边 + 内嵌强弱标签 |
| 扫描进度条 | 渐变填充 + 循环高光扫过，明确「仍在推进」 |
| 面板/弹窗入场 | `cubic-bezier(.32,.72,0,1)` 位移淡入 |
| 按压反馈 | 工具栏按钮 `scale(0.97)` |
| 无障碍 | `prefers-reduced-motion` 下全部动画降到 0.01ms；焦点环 `outline` 可见 |

### 视觉校验中发现并修掉的 6 个真实缺陷

用 Playwright 截图逐轮比对，这些问题肉眼读代码时都没发现：

1. **折叠箭头把标题挤到右侧** —— `.sc-arrow` 在 DOM 中位于标题文本**之前**，
   我给它加了 `margin-left:auto`，导致整个卡片标题右对齐。
2. **卡片内容被裁切** —— `.right-panel` 改成 flex 容器后，子项默认可收缩，
   「操作计划」卡片内容被压掉一半。需显式 `flex: 0 0 auto`。
3. **决策环从底部起画** —— `conic-gradient(from 180deg)` 起点在 6 点钟方向，
   仪表盘惯例是 12 点。
4. **深度条 22% 不透明度读不出强弱**，且中性档的黄色在低透明度下呈军绿泥色
   → 提到 32% 并把中性档换成中性蓝灰 `#8b95a3`。
5. **`.ml-name` 64px 装不下「技术指标共振」** → 换行破坏行高，改为
   72px + 省略号，并把标签缩短为「指标共振」。
6. **`_lastSymbol` 变量重名** —— 我新增的价格闪烁状态变量与第 2945 行既有的
   `const _lastSymbol` 撞名，直接导致整个脚本块 `SyntaxError` 白屏。
   这是最危险的一个，纯静态检查发现不了。

### 文案改动

- `信号中` → `强度 中`。原文案会被读成「正在出信号」，实际含义是
  「信号强度=中」。
- `综合基本面` → `综合评估`。CANSLIM 模块实际未接任何财务数据（见
  `docs/ANALYSIS.md` 局限性第 1 条），原标签属于误导。

## D9 · 图表主题与 12 个缺陷（v5.2）

上一轮只重做了右侧面板，占屏 60% 的图表区几乎没动，结果整体观感割裂
（白底 tooltip、军绿 dataZoom、资金流整块红）。本轮把图表纳入同一套视觉系统，
并借视觉排查发现了一批功能性缺陷。

### 根因：`setOption(..., true)` 与全局样式互斥

原实现在 `initCharts()` 里用 `chart.setOption(opts)` 注入配色，但业务代码
后续全部使用 `setOption(newOption, true)` —— 第二个参数 `notMerge=true`
会**整体丢弃**已有 option，包括 tooltip 样式。于是 K 线 tooltip 退回
ECharts 默认的白底圆角卡片，在暗色终端里格外突兀。

**正确做法**：`echarts.registerTheme('qsdark', {...})` + `echarts.init(dom, 'qsdark')`。
主题独立于 option，不受 `notMerge` 影响。

### 修掉的 12 个缺陷

| # | 缺陷 | 类型 | 说明 |
|---|---|---|---|
| 1 | K 线 tooltip 白底 | 视觉·根因 | 同上，改用 registerTheme |
| 2 | MA 线与 tooltip 颜色对不上 | 视觉 | 系列只设了 `lineStyle.color`，而 tooltip 的 `p.color` 取自 `itemStyle`/调色板，于是图上金紫蓝青、tooltip 里蓝绿黄红 |
| 3 | dataZoom 填充呈军绿泥色 | 视觉 | 上一轮正则只匹配 `#ff9800`，漏了 `rgba(255,152,0,…)` 写法 |
| 4 | 谨慎买入横幅同样残留橙色 | 视觉 | 同上 |
| 5 | 资金流图是一整块红板 | 视觉 | 240 根 1 分钟柱挤在 100px 高的图里。累计量本质是连续曲线，改为渐变面积图 |
| 6 | **准确率恒为 0%** | 功能 | `prev.action === '买入'` 全等匹配，但优化器输出的是「强烈买入 / 谨慎买入」。谨慎买入后涨 2.5% 仍被判错 |
| 7 | 买入/卖出/观望计数恒为 0 | 功能 | 同一处全等匹配 |
| 8 | 自选、多股一览、历史、变更提示的信号标签方向错乱 | 功能 | 同类全等匹配扩散到 6 处，「强烈买入」被染成观望黄 |
| 9 | 信号说明面板永久压住 K 线 | 交互 | 只有 `position:absolute`，JS 从未设置 `left/top`，永远落在容器左上角。改为定位到光标对侧并做上下翻转 |
| 10 | 信号说明面板闪烁 | 交互 | 缺 `pointer-events:none`，鼠标移入面板会打断 zr 的 mousemove |
| 11 | markLine 2px 粗线横贯全图、标签压住 Y 轴刻度 | 视觉 | 改为 1px 细线 + 标签移到右侧（与价格轴同侧，TradingView/交易所通行做法），文案压缩为单行 |
| 12 | **五个副图指标永久不可用** | 功能·死锁 | 见下 |

### 第 12 项：一个存在已久的死锁

```
工具栏初始 display:none
  → 仅当 _currentIndicator !== 'none' 时才显示
  → _currentIndicator 只能由工具栏内的按钮点击改变
  → 按钮在隐藏的工具栏里，永远点不到
```

MACD / RSI / KDJ / BOLL / WR 五个指标自 v4.0 起从未能被打开。
讽刺的是，v5.0 新增的 `technicalIndicators.ts` 正好算的就是这几个指标，
后端算完了前端却没有入口。

修复：日K/周K 视图下工具栏常显，「副图」按钮本身作为关闭开关。

### 排查方法

第 6、7、8、12 项都是**功能性缺陷，靠读代码和类型检查都发现不了**
（TypeScript 只覆盖后端，前端是单文件 vanilla JS）。它们是这样被找到的：

1. 用 Playwright 加载注入了模拟数据的页面，**截图逐帧比对**（第 1~5、9~11 项）
2. 写一个交互扫描脚本，**自动点遍所有控件**并监听 `console.error` /
   `pageerror`（第 12 项即由「按钮点不到」超时暴露）
3. 从截图里的异常数值反查逻辑（第 6 项：界面显示「准确率 0%，
   信号次数 1，买入 0」，而明细行写着「+2.5% ✓」，自相矛盾）

交互扫描脚本值得保留复用，见 `tools/ui-audit.mjs`。

## D10 · 排版修复（v5.6）

### 图表右侧价格标签叠成一团

6 条价格线的标签全部贴在右侧同一列，价位接近时直接互相覆盖
（733.6 被 743.10 压住、636.45 被 652.14 压住）。ECharts 的 `markLine.label`
**没有互斥避让能力**，必须自己处理。三层解决：

1. **方向过滤** —— 当前建议买入时，海龟系统的「历史做空」线只是噪声，不显示
2. **重要度限量** —— 按 计划买入 > 计划止损 > 形态目标 > 海龟止损 > 历史入场
   排序，超过 5 条的降级为无标签细线
3. **左右分列** —— 纵向间距小于价格区间 4.5% 的标签交替换到左侧

### Y 轴底部大片留白

数据区间 565~960，坐标轴却从 400 起画，底部 25% 画布空着。
原因是中枢 `markArea` 参与了轴范围计算。

第一次修复用了函数式 `min`/`max`，结果轴上冒出 `99999999` ——
ECharts 在 markLine 参与统计时会传入异常的 `v.min/v.max`。
改为**在 setOption 前用 K 线数据算好数值**，并且只把落在 K 线区间外 25% 以内的
价格线纳入范围。同时隐藏首尾两个非整数刻度（`928.3694` 这种）。

### 两个互相打架的仓位数字

面板同时显示「轻仓(1/4)」（=25%）与「反推权重 8.2%」，相差三倍，
用户不知道该听谁的。二者口径不同：

- 档位仓位：优化器按大盘 M 分给的粗档
- 风险仓位：按单笔 1% 风险 ÷ 止损距离反推

真正该执行的是**两者取小**。已改为直接给出「实际建议仓位 8.2%」，
并在下方注明取小依据，消除歧义。

### 长文案把词拆到下一行

「建议仓位 轻仓(1/4) — 大盘偏空，严格控制仓位」在「左标签／右值」的两栏
布局里，会把「钱」「盈亏比」这类词孤立到下一行。
改为按 `—` 拆分：主值留在行内右对齐，理由独立成行。

- 成交量轴 `250,000` 改为 `25万`，省出横向空间
- `plan-row` 增加 `.stacked` 变体，值过长时自动上下排
