# 买入价与「AI 结论」的三个问题，以及入场策略参数

本文回答四个具体质疑，并说明新增的入场过滤层。

---

## 一、为什么图表和卡片的买入价对不上

它们来自**两个完全不同的数据源**，而原界面没有任何标注：

| 界面位置 | 显示 | 实际含义 | 数据来源 |
|---|---|---|---|
| 图表 `入场 14.45` | 14.45 | **几天前**海龟法则突破时的入场价 | `breakouts[].entry_price` |
| 图表 `止损 12.70` | 12.70 | 基于那个**历史**入场价的 2N 止损 | `breakouts[].stop_loss` |
| 图表 `目标 11.29` | 11.29 | 某个**看跌**形态的下行目标位 | `patterns[].target_price` |
| 卡片 `买入价 17.34` | 17.34 | **当前**收盘价 | `trade_plan.entry_price` |
| 卡片 `止损 16.47` | 16.47 | 当前价 × 0.95 | `trade_plan.stop_loss` |
| 卡片 `目标 19.07` | 19.07 | 当前价 × 1.10 | `trade_plan.target_price` |

三个具体缺陷：

**1. 标签词不达意**。`入场 14.45` 会被读成「现在按 14.45 买」，实际那是历史突破价。
→ 已改为 `历史突破 14.45` / `海龟止损 12.70`，并把当前计划价位也画到图上（金色 `计划买入`）。

**2. 方向标反了**。截图里 `目标 11.29 涨到这里就卖` 位于现价 17.34 **之下**——
那是看跌形态的下行目标，标签却写「涨到这里」。原因是代码用整体信号方向
（`isBearish`）给所有形态目标贴标签，没有看**该形态自身**的方向。
→ 已改为按每个形态自己的 `direction` 判定，并且方向与位置矛盾时**不画这条线**。

**3. 盈亏比恒等于 2.0**。这是最需要知道的一点：

```
stop   = entry × 0.95      ← 硬编码 −5%
target = entry × 1.10      ← 硬编码 +10%（无可用形态目标时）
盈亏比 = 10% / 5% = 2.0    ← 两个常数的算术结果
```

界面上那句「⚠ 盈亏比2，风险收益比良好」是循环论证——它在夸奖两个写死的数字。
它不包含任何关于这只股票的信息。

## 二、没有买入时间点

原实现的 `action` 是**时点快照**，不记录「信号何时首次出现」。图上只有缠论买卖点
带日期，主信号没有。这也是回测暴露换手问题的同一个根源：`action` 不是持仓状态。

已加入：图表绘制当前 `计划买入 / 计划止损` 横线，与右侧卡片同源；
持仓判定改用滞后带（进 62 分 / 出 45 分 / 最短持仓 5 日）。

## 三、「AI 分析结论」里没有 AI

直接回答：**整条链路不涉及任何 AI 模型**。

- 没有调用大语言模型
- 没有机器学习、没有训练过的预测模型
- 没有任何外部推理接口

唯一的外部接口是**行情数据**：腾讯 / 新浪 / 东方财富的公开接口（K线、实时报价、
资金流、涨跌家数）。

结论 100% 来自确定性规则计算：

```
六模块各自算分 → 固定权重加权求和取整 → 五级重评 → 硬/软否决 → 仓位与盈亏比检查
```

同样的输入永远得到同样的输出，没有任何随机性或模型推断。所有阈值
（60/75 分线、±2%、±30%…）都是**经验值**，未经回测证明。

→ 卡片标题已从「AI 分析结论」改为「量化规则结论」，并加了「计算依据」按钮，
点开会明确写出以上内容 + 当前权重 + 本次各模块得分。

沿用「AI」这个词会让人过度信任输出，这是我认为必须改掉的表述。

## 四、新增：入场过滤层（`src/analysis/entryFilters.ts`）

回到截图那个例子。300394 当时的状态是：

```
+20.00%（创业板涨停）   换手 26.3%   主力净流出 3.83 亿
界面结论：谨慎买入   风险「低」   置信度 78%   买入价 17.34
```

**17.34 这个价格根本买不到**——涨停板上没有卖盘。而「主力净流出 3.83 亿 +
换手 26.3% + 涨停」是教科书式的对倒出货形态，界面却判风险「低」。

新增的过滤层专门处理这类「评分很高但执行不了」的情况。全部采用有公开出处的通行规则：

| 过滤器 | 依据 | 默认参数 |
|---|---|---|
| **涨停不可买** | A股微观结构：涨停板无卖盘 | 涨幅 ≥ 97% 涨停幅度 |
| **跌停不可卖** | 同上 | 跌幅 ≥ 97% 跌停幅度 |
| **停牌** | 成交量为 0 | — |
| **流动性下限** | 成交额过小时滑点不可控 | 20日均额 ≥ 5000万 |
| **出货形态** | 涨停+高换手+主力净流出 | 换手 ≥ 15% 且主力净流出 |
| **大盘择时** | Faber (2007) 长期均线规则 | 指数 > MA200 |
| **追高过滤** | 偏离均线过远时回归风险占优 | 距 MA20 ≤ 15% |
| **量能确认** | O'Neil：有效突破需放量 | 量比 ≥ 1.2 |
| **风险预算定仓** | 海龟法则：单笔风险固定 1% | risk=1%, 2×ATR 止损 |

拿截图那只股票实测：

```
可交易: false
  [block] LIMIT_UP:      已涨停(20.00%/20%)，涨停板无卖盘，此价位无法成交
  [block] DISTRIBUTION:  换手26.3%、涨20.0%，但主力净流出3.83亿 —— 对倒出货特征
  [warn]  WEAK_VOLUME:   量比0.96低于1.2，突破缺乏量能确认
```

`block` 级别的发现会作为**最高优先级硬否决**进入优化器——分数再高也执行不了，
所以它排在所有技术面否决之前。

同时用结构位替换硬编码百分比：

```
止损 = max(2×ATR止损, 20日通道下轨, 近20日最低)   取最靠近现价的
目标 = min(看涨形态目标, 箱体上沿, 近60日前高, 通道上轨+1ATR)   取最近的
仓位 = 单笔风险预算 ÷ 单股风险距离              上限受单票权重约束
```

同一只股票的对比：

| | 原实现 | 结构化 |
|---|---|---|
| 止损 | 16.47（−5%） | 15.58（2×ATR=0.88） |
| 目标 | 19.07（+10%） | 24.78（近60日前高） |
| 盈亏比 | 2.00（恒定） | 4.22（实际测算） |
| 建议权重 | 固定档位 | 9.8%（对应 1% 单笔风险） |

## 五、必须说清楚：这些改动我**没有**证明是改进

新增的 A/B 开关跑了三组对比（合成数据，25 只 × 700 根）：

| 配置 | 累计收益 | Sharpe | 最大回撤 | 平均持仓 | 平均仓位 |
|---|---|---|---|---|---|
| **A** 原实现（−5%/+10%） | +30.44% | **1.66** | −4.67% | 17.2 日 | 40.0% |
| **B** 仅结构化止损/目标 | −0.52% | −0.54 | −6.29% | 8.1 日 | 15.4% |
| **C** 全开（+过滤+风险仓位） | −0.98% | −0.63 | −5.88% | 8.2 日 | 14.6% |

**结构化止损在这份数据上把结果做坏了**，而且差距很大。

原因可诊断：合成序列的日波动约 2%，2×ATR ≈ 4% **比固定 5% 更紧**，
于是频繁被打止损（持仓 17.2 → 8.1 日），仓位也随之下降。
而在真实的 300394 上，2×ATR = 10.1% **反而比 5% 宽**。

所以结论是：**`atrStopMult` 是一个必须用你自己的数据校准的参数，
不是一个默认更优的改进**。我把它做成可优化参数，而不是替你决定。

顺带说明：A 组那个 Sharpe 1.66 也**不能**当成好消息——合成数据里
我人为放进了持续漂移和周期，趋势策略当然能抓到。真实市场没有这种结构。

## 六、你该怎么用这些开关

```bash
# 1. 先拿真实数据跑三组 A/B，看结构化止损在你的市场里是帮忙还是帮倒忙
npm run bt -- run --data backtest/data --benchmark backtest/benchmark.csv \
    --no-filters --no-structural --no-risk-sizing        # A 基线
npm run bt -- run --data backtest/data --benchmark backtest/benchmark.csv \
    --no-filters --no-risk-sizing                        # B 加结构化止损
npm run bt -- run --data backtest/data --benchmark backtest/benchmark.csv   # C 全开

# 2. 单独测大盘择时的价值（Faber 规则在A股是否成立，值得自己验）
npm run bt -- run --data backtest/data --regime-ma 0     # 关闭
npm run bt -- run --data backtest/data --regime-ma 200   # 开启

# 3. 校准 ATR 倍数与单笔风险
npm run bt -- run --data backtest/data --risk-per-trade 0.005
npm run bt -- run --data backtest/data --max-ext 10

# 4. 最后做样本外检验 —— 只有这一步的结论可参考
npm run bt:wf -- --data backtest/data --benchmark backtest/benchmark.csv
```

判读标准仍然是那三条：**衰减幅度 < 50%**、**样本外 Sharpe 超过噪声上界**、
**交易笔数 ≥ 30**。三条里有任何一条不过，正确动作是不用它，而不是继续调参。

## 七、图表被一根 K 线毁掉（v5.5 修复）

### 现象

北方华创（743.50）的图上出现一根从 ~750 直插到接近 0 的巨型红线，
y 轴被迫从 0 起画，真实价格结构被压进面板顶部 1/4，整张图不可读。
同时右侧告警「量比 0.09 低于 1.2，突破缺乏量能确认」。

### 原因一：数据校验只做了一半

`validateKlines` 只检查**结构一致性**和一个绝对上限：

```ts
k.close > 0 && k.high > 0 && k.low > 0 && k.open > 0
&& k.high >= k.low && k.high >= k.close && k.high >= k.open
&& k.low <= k.close && k.low <= k.open
&& k.close < 10000
```

一根 `low=0.5, high=750, close=743` 的脏数据**通过全部 8 项检查**：
high≥low 成立、low≤close 成立、close<10000 也成立。

缺的是**量级合理性**。A股有涨跌停限制，单日振幅存在物理上限：

| 板块 | 涨跌幅 | high/low 上限 |
|---|---|---|
| 主板 | ±10% | 1.222 |
| 双创 | ±20% | 1.500 |
| 北交所 | ±30% | 1.857 |

而这根脏数据的 high/low = **1500**。

后果不止是图丑：ATR、N 值、唐奇安通道下轨、止损价全部被这一根污染，
**而界面不会有任何异常提示**，因为每一项校验都"通过"了。

**修复**：新增两道量级校验 —— 单日 `high/low ≤ 2.2`（留出复权、新股首日、
长停复牌的余量），相邻日收盘跳变 `≤ 2.5 倍`。丢弃时打 `console.warn` 留痕。
前端另加一道同口径的兜底过滤，因为缓存里可能还留着旧脏数据，
而一根坏数据毁掉整张图的代价太大，值得双保险。

### 原因二：量比拿 5 分钟去比全天

截图时是开盘不久（量 7634 手、换手 0.1%）。原实现：

```ts
volumeRatio = quote.volume / avg5_全天成交量
```

拿**当日累计量**直接比**过去 5 日全天均量**。开盘 5 分钟时，
任何股票的量比都只有真实值的 1/48。

市场通行定义是**时间归一化**的：

```
量比 = (当日累计量 ÷ 已开市分钟数) ÷ (过去5日平均每分钟成交量)
```

修正效果（同一只股票，原始量比 0.09）：

| 北京时间 | 已开市 | 修正倍数 | 修正后量比 |
|---|---|---|---|
| 09:35 | 5 分钟 | ×48.0 | **4.32** |
| 10:00 | 30 分钟 | ×8.0 | 0.72 |
| 11:30 | 120 分钟 | ×2.0 | 0.18 |
| 14:55 | 235 分钟 | ×1.0 | 0.09 |

不修的话，`minVolumeRatio: 1.2` 这条过滤器在**每天 14:00 之前会拦掉几乎所有标的**——
一个 100% 误报的告警比没有告警更糟。

**修复**：新增 `src/util/tradingClock.ts` 计算北京时间已开市分钟数
（含午休处理），实盘路径传入做归一化；开市不足 30 分钟时样本太少，
直接跳过量能判定。

**回测与 legacy 档位不传该参数**，沿用全天口径 —— 历史 K 线本来就是全天数据，
归一化会引入错误，而且必须保证回测结果可复现。55 项一致性测试因此仍全绿。

### 顺带说明截图里两个看着矛盾的地方

**「风险 低」但「置信度 32%」**：两者算法无关。风险等级由趋势方向、
量价方向、M 分、止损信号四项累加判定；置信度是
`max(10, int(score×0.8) + 12×达标模块数 − 40)`。61 分、2 个模块达标 →
48+24−40 = 32。两个数字并排显示容易被误读成互相矛盾，但它们量的不是同一件事。

**图上「海龟止损 808.77」高于现价 743.50**：那是**做空**方向的止损
（对应上方的「历史做空 904.80」）。海龟系统同时给出多空两侧的历史入场与止损，
而当前建议是买入，两者并存看着别扭但各自成立。
